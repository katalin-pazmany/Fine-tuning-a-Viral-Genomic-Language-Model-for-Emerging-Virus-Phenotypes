# Fine-tuning a Viral Genomic Language Model for Emerging Virus Phenotypes

MSc project (COMP702), University of Liverpool. Supervisor: Dr Maya Wardeh.

Predicting three viral phenotypes directly from genome sequence — **human-to-human
transmissibility**, **zoonotic potential**, and **vector-borne (vertebrate-crossing) transmission** —
and asking whether a pre-trained viral genomic language model (**Vir2vec**) is actually worth its
cost compared with cheap classical baselines.

## Headline findings

1. **Frozen embeddings beat fine-tuning.** A shallow classifier on frozen Vir2vec embeddings
   (Tier 1) outperforms both partial unfreezing (Tier 2) and LoRA (Tier 3) on every phenotype.
2. **Cheap baselines are competitive.** Under cross-validation, $k$-mer and codon-usage composition
   match or beat the 422M-parameter model.
3. **On genuinely novel viruses the model has no advantage.** Using Vir2vec's *published
   pre-training accession lists*, every virus was labelled seen/unseen by the model. Training only on
   seen viruses and predicting unseen ones — the real emerging-virus setting — leaves Vir2vec at or
   below every composition baseline, and for human-to-human transmission significantly worse than
   codon usage or $k$-mers (bootstrap p < 0.001).

## Repository layout

| Path | Contents |
|---|---|
| `pipeline/` | The three modelling tiers (frozen embeddings, partial unfreeze, LoRA) for the H2H/zoonotic and vector-borne tasks. |
| `scripts/` | Data prep, labelling, deduplication, baselines, benchmarks and analyses (see below). |
| `scripts/slurm/` | SLURM submission scripts used on the Barkla HPC cluster. |
| `outputs/` | Results (JSON/CSV), figures, deduplication cluster tables, misclassification analyses. |
| `data/` | Phenotype labels and small reference tables. Bulk sequence data is **not** committed (see below). |
| `network-viz/` | Interactive network visualisation of the embedding space. |

### Key scripts

- `scripts/dedup_sequences.py` — CD-HIT-EST deduplication at 90% identity (leakage control).
- `scripts/baseline_comparisons.py` — majority-class, GC+length, $k$-mer, codon-usage baselines.
- `scripts/blast_baseline.py` — BLAST nearest-neighbour baseline.
- `scripts/mollentze_benchmark.py` — external benchmark vs Mollentze et al. (2021).
- `scripts/intact_validation.py` — orthogonal virus–human protein interaction check.
- `scripts/make_vir2vec_seen_labels.py` — labels each virus seen/unseen by Vir2vec's pre-training corpus.
- `scripts/seen_unseen_analysis.py` — the out-of-distribution evaluation (the headline result).
- `scripts/seen_unseen_significance.py` — bootstrap confidence intervals and significance tests.

### Key results files

- `outputs/results_summary_final_dedup.csv` — main three-tier comparison, all phenotypes.
- `outputs/seen_unseen_results.json` — seen/unseen out-of-distribution evaluation.
- `outputs/seen_unseen_significance.json` — bootstrap CIs and p-values.
- `outputs/baselines_dedup/`, `outputs/baselines_vector_borne_dedup/` — baseline results.
- `outputs/misclassification_dedup/` — per-family / per-host-group error rates.

## What is intentionally not committed

To keep the repository usable, large files that are public or regenerable are excluded
(see `.gitignore`):

- **Model weights** (`models/`, ~1.1 GB). Vir2vec is public — download it from
  <https://huggingface.co/pabloarozarenad/Vir2vec>. Its pre-training accession lists are at
  <https://github.com/simoRancati/Vir2vec>.
- **Bulk sequence data** (`data/raw_matched/`, the large FASTAs). Re-downloadable from NCBI using the
  retrieval scripts in `scripts/`.
- **Cached embeddings** (`outputs/refseq_embeddings.npz`, 43 MB) — regenerated by running the
  embedding extraction over the retrieved sequences.

## Environment

Python with scikit-learn, PyTorch, HuggingFace `transformers`, PEFT and Biopython. CPU is sufficient
for the frozen-embedding and baseline analyses; Tier 2 and Tier 3 fine-tuning were run on NVIDIA
L40S GPUs on the University of Liverpool Barkla cluster. All random seeds fixed
(`random_state = 42`) for reproducibility.

> Note: when running the fine-tuning tiers on a compute node, set `HF_HUB_OFFLINE=1` and
> `TRANSFORMERS_OFFLINE=1` so the cached Vir2vec model is used rather than re-fetched.
